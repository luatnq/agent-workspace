Agent-Ready Codebase Scorecard

Khung đánh giá định lượng 100 điểm và phương pháp audit biến một codebase truyền thống thành môi trường phát triển lý tưởng cho Autonomous Coding Agent.

1. Bốn trụ cột của Agent-Readiness

Trụ cộtBản chất cốt lõiRào cản thường gặpGiải pháp Agent-Ready
1. Structure & Discoverability Repo tự diễn giải, ranh giới module rõ ràng, tài liệu hóa quy ước khác thường. Monorepo lộn xộn, tài liệu thất lạc trên Confluence, không có instruction file chuẩn. File AGENTS.md ngắn gọn (<200 dòng), bố cục thư mục chuẩn Maven/Gradle, non-standard conventions rõ ràng.
2. Deterministic Environment Môi trường build đóng gói hermetic, một lệnh chạy ngay, không phụ thuộc máy cá nhân. Cài đặt môi trường thủ công tốn 2 ngày, phụ thuộc biến môi trường ngầm định. Wrapper script chuẩn (./mvnw, ./gradlew), docker-compose.yml cho DB/Redis, file .env.example.
3. Verifiability & Fast Gates Vòng lặp xác minh siêu tốc để agent chạy ReAct (gather $\to$ act $\to$ verify). Test suite chạy mất 40 phút; linter chỉ chạy trên CI; lỗi chỉ bắt được khi build production. Lệnh unit test subset chạy <30s, tool auto-format CLI (spotlessApply), PostToolUse hook tự kiểm tra.
4. Safety & Guardrails Rào chắn bảo vệ ngăn chặn agent phá hoại hoặc làm rò rỉ thông tin nhạy cảm. Hardcoded secrets trong repo, agent có thể chạy DROP TABLE hoặc sửa file migration. PreToolUse hook chặn sửa db/migration/*.sql, secret scanner (gitleaks), tài khoản DB dev bị giới hạn quyền.

2. Bảng chấm điểm Agent-Ready Scorecard (100 điểm)

#Tiêu chí đánh giáĐiểm tối đaYêu cầu đạt điểm tối đa (Full Score)
1 Instruction File (AGENTS.md) 10 Có file ở root, <200 dòng, chứa lệnh build/test chuẩn, liệt kê non-standard conventions, không nhồi nhét văn xuôi thừa.
2 Hermetic Build & Dependency 10 Có wrapper (./gradlew / ./mvnw), dependency được lock version rõ ràng, không yêu cầu cài SDK toàn cục.
3 Fast Feedback Test Suite 10 Có lệnh chạy unit test subset của 1 class/package hoàn thành trong dưới 15 giây.
4 Automated Formatting & Linting 10 Có lệnh CLI sửa format tự động (ví dụ ./gradlew spotlessApply), chạy <5 giây.
5 Deterministic Local Dependencies 10 Mọi phụ thuộc ngoại vi (PostgreSQL, Kafka, Redis) dựng được bằng 1 lệnh docker compose up -d hoặc Testcontainers.
6 Static Typing & Explicit Contracts 10 Tận dụng Java Strong Typing, DTO có validation annotations (@NotNull, @Valid), API có OpenAPI/Swagger.
7 Package Cohesion & Clean Boundaries 10 Phân tách domain/layer rõ ràng (Clean / Hexagonal Architecture), không có quan hệ phụ thuộc vòng tròn (circular dependency).
8 Automated Guardrails & Hooks 10 Có Lifecycle Hook ngăn chặn việc sửa đổi file migration database nhạy cảm hoặc chạy lệnh bash phá hủy.
9 Mocking & Fixtures Readiness 10 Có sẵn bộ dữ liệu mẫu (test fixtures) và Mockito mocks chuẩn để agent viết test mà không cần truy cập network ngoài.
10 Clean Logging & Actionable Errors 10 Thông báo lỗi compiler/test rõ ràng, không in stacktrace rác hàng nghìn dòng làm tràn context window.

3. Phân loại cấp độ sẵn sàng

  • 0 – 39 điểm: Agent-Hostile (Thù địch với Agent)
    Agent vào là kẹt: không thể build local, test mất hàng giờ hoặc lỗi tùm lum, thiếu thông tin môi trường. Agent sẽ làm hỏng code hoặc làm cháy ngân sách token.
  • 40 – 70 điểm: Agent-Tolerant (Chấp nhận được)
    Agent làm việc được nhưng cần người dùng cầm tay chỉ việc, phải copy-paste lỗi thủ công, chi phí token cao do context bị ô nhiễm.
  • 71 – 90 điểm: Agent-Friendly (Thân thiện)
    Agent tự khám phá code, sửa mã nguồn, tự chạy unit test và linter để sửa sai. Năng suất lập trình tăng rõ rệt (2–3x).
  • 91 – 100 điểm: Agent-Native (Tự hành hoàn hảo)
    Codebase được tối ưu hóa như một API: agent nhận task, tự phân nhánh git worktree, tự code, tự verify qua test gate/lint gate và tạo Pull Request kèm báo cáo sạch sẽ.

4. Danh sách hành động ưu tiên (Prioritized Action Plan)

  1. Quick Wins (Làm trong 1–2 giờ — ROI cao nhất):
    • Tạo AGENTS.md chuẩn ở root repo (lệnh build, lệnh test 1 class, format style).
    • Cấu hình lệnh auto-format (Spotless / Prettier) vào package/build script.
  2. Medium-term (Làm trong 1–2 ngày):
    • Chia tách test suite: tách riêng Unit Tests (nhanh) và Integration Tests (chậm).
    • Gắn PostToolUse hook chạy linter và unit test tự động sau mỗi lần Edit.
    • Tạo docker-compose.yml cho các dependency local.
  3. Long-term (Cải tiến kiến trúc):
    • Dọn dẹp circular dependencies, đóng gói DTO/Contract rõ ràng.
    • Tích hợp Testcontainers và fixtures test tái sử dụng.
