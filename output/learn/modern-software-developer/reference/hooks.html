Lifecycle Hooks

Thực thi code tất định tại các điểm neo vòng lặp của agent: cưỡng chế quy tắc an toàn (guardrail) và tự động hóa kiểm thử (lint/test gate).

Instruction vs Hook

Tiêu chíInstruction (AGENTS.md / CLAUDE.md)Hook (Lifecycle script)
Bản chấtGợi ý ngữ cảnh (soft guideline) nạp vào promptCode thực thi tất định (hard constraint) do harness chạy
Cơ chế đảm bảoDựa vào khả năng suy luận xác suất của modelDựa vào exit code của hệ điều hành (POSIX standard)
Nguy cơCó thể bị model quên hoặc bỏ qua khi context dàiKhông thể vượt rào (bypass) nếu vi phạm
Chi phí tokenTốn token ở mọi lượt chat (nằm trong context)Không tốn token trừ khi script in ra lỗi cần model sửa
Tương đương BackendComment trong code: // Don't deleteDatabase Constraint / Servlet Filter / Interceptor

Các điểm neo vòng lặp (Lifecycle Events)

Điểm neoThời điểm kích hoạtMục đích sử dụng chính
PreToolUse Ngay trước khi tool thực thi trên đĩa Guardrail / Chốt an toàn: Chặn sửa migration database, chặn lệnh bash phá hoại, kiểm tra quyền truy cập.
PostToolUse Ngay sau khi tool chạy xong Verification Gate: Chạy linter (Spotless), chạy nhanh unit test, biên dịch thử. Trả stderr cho model tự fix.
PreInvocation Trước khi gửi prompt cho model Kiểm tra môi trường, nạp bổ sung biến động nếu cần.
PostInvocation Sau khi toàn bộ tool call của lượt hoàn tất Ghi nhận log, audit số token, thông báo trạng thái.
Stop Khi kết thúc phiên làm việc Dọn dẹp tài nguyên tạm, đóng kết nối.

Giao thức điều khiển Exit Code

  • Exit Code 0: Cho phép tiếp tục. Harness thực thi tool hoặc trả kết quả về cho model.
  • Exit Code khác 0 (Exit 1 / 2):
    • Với PreToolUse: Tool bị hủy bỏ hoàn toàn (abort), không ghi file.
    • Với PostToolUse: Bắt toàn bộ text in ra stderr đưa vào context ở turn kế tiếp làm thông báo lỗi để model tự sửa.

Cấu hình trên các Harness

1. Antigravity (.agents/hooks.json)

{
  "guard-migration": {
    "PreToolUse": [
      {
        "matcher": "replace_file_content",
        "hooks": [
          { "type": "command", "command": "./scripts/hooks/guard-migration.sh", "timeout": 5 }
        ]
      }
    ]
  },
  "java-lint-gate": {
    "PostToolUse": [
      {
        "matcher": "replace_file_content",
        "hooks": [
          { "type": "command", "command": "./scripts/hooks/check-java.sh", "timeout": 15 }
        ]
      }
    ]
  }
}

2. Claude Code (.claude/config.json)

{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Edit", "command": "./scripts/hooks/guard-migration.sh" }
    ],
    "PostToolUse": [
      { "matcher": "Edit", "command": "./scripts/hooks/check-java.sh" }
    ]
  }
}

Quy tắc vàng khi viết Hook

  1. Chạy cực nhanh (< 5 giây): Hook chạy đồng bộ giữa các lượt chat của agent. Đừng đưa full test suite vào hook. Chỉ chạy syntax check, linter hoặc unit test của file vừa sửa.
  2. Thông báo lỗi phải actionable: In ra stderr thông điệp rõ ràng, nêu đích danh lý do bị chặn và hướng dẫn model cách sửa (vd: "Hãy tạo file migration mới V...__xxx.sql").
  3. Tách logic ra script shell độc lập: Viết script trong scripts/hooks/ để dùng chung cho mọi harness và dễ dàng test bằng tay trên terminal.
