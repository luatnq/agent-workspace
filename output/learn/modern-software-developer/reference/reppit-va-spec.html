RePPIT & spec-driven

Nghi thức tỉ lệ với độ lớn và độ lạ của việc. Duyệt tài liệu có đòn bẩy lớn hơn duyệt code. Xóa context giữa các bước.

Vài file, codebase quenPlan mode → duyệt → làm

RePPIT

BướcOutputLuật
ResearchMD 100–300 dòng, hiện trạng codebase, có file:dòngKhông đề xuất. Chạy mới mỗi lần, không commit. Anh duyệt.
ProposeĐúng 2 phương án: tổng quan, thay đổi chính, trade-off, cách kiểm tra, câu hỏi mởHai phương án khác nhau thật. Anh chọn.
PlanDesign doc: yêu cầu, quyết định + lý do, data model, tích hợp, file sửa / không sửa/clear trước khi chạy. Anh duyệt.
ImplementCode theo planPlan đủ tốt thì không còn chỗ để đoán
TestReview + testInstance khác hoặc model khác review. Anh duyệt.

Nguồn: Mihail Eric; nền tảng: ACE-FCA (giữ context ở 40–60%, compaction có chủ đích).

Prompt mẫu

# Research
Nghiên cứu codebase cho ticket: <ticket>. Chỉ mô tả hiện trạng
(file liên quan, luồng dữ liệu, điểm tích hợp, test hiện có).
KHÔNG đề xuất. Ghi vào research.md, 100–300 dòng, có file:dòng.

# Propose  (sau /clear)
Đọc research.md và ticket. Đưa ĐÚNG HAI phương án khác nhau thật sự:
tổng quan, thay đổi chính, trade-off, cách kiểm tra, câu hỏi mở.

Spec-driven: ba mức (Böckeler)

MứcRủi ro
Spec-firstÍt
Spec-anchoredSpec lỗi thời
Spec-as-sourceCứng nhắc + không tất định

Công cụ: Spec Kit (constitution → specify → plan → tasks → implement → converge), Kiro (requirements / design / tasks, EARS: WHEN … THE SYSTEM SHALL …).

Prompting 2026

  • Giữ: cụ thể (file, pattern, triệu chứng); cho cách tự kiểm tra; ví dụ mẫu; XML tag.
  • Bỏ: viết hoa gây sức ép; prefill (400 từ Claude 4.6); "think hard" (chỉ ultrathink là từ khóa).
  • Context file: tổng quan repo không giúp ích (+20% chi phí); chỉ ghi quy ước khác thường (Gloaguen et al. 2026).
