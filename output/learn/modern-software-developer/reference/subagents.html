Subagent & Multi-agent Patterns

Kiến trúc đa tác tử trong coding agent: phân rã ngữ cảnh (Context Isolation), chuyên biệt hóa vai trò (Specialization), và cơ chế bàn giao thông qua Artifact thay vì chat tự do.

1. Vì sao cần Subagent? Bài toán Context Isolation

Khi đối mặt với codebase lớn, một tác tử duy nhất (Single "God" Agent) nhanh chóng rơi vào bẫy Context Rot và Lost in the Middle. Nếu agent phải mở 30 files mã nguồn để khảo sát kiến trúc, context phình to lên 150k tokens, dẫn đến:

  • Chi phí tăng vọt: Mọi lượt gọi tool hay suy nghĩ sau đó đều phải trả tiền đọc lại 150k tokens rác từ quá trình đọc file trước đó.
  • Độ trễ (TTFT) cao: Xử lý prompt khổng lồ làm chậm vòng lặp phản hồi.
  • Ảo giác & phân tâm: Model mất khả năng chú ý vào các ràng buộc kỹ thuật cốt lõi.

Giải pháp Subagent (Context Fork): Tách tác vụ khám phá cho một subagent chạy trong ngữ cảnh cô lập (fork). Subagent đọc 30 files, tốn 40k tokens trong ngữ cảnh tạm, nhưng chỉ trả về một bản tóm tắt ngắn (500 tokens) cho main agent. Toàn bộ rác trung gian được "thu gom rác" (Garbage Collected) khỏi context chính.

3. Cơ chế Harness: Claude Code vs Antigravity

Tính năngClaude CodeAntigravity
Cơ chế cô lập context: fork trong skill/agent definition. Subagent chạy trên bản sao ngữ cảnh tạm. Subagent chạy độc lập; hỗ trợ chế độ workspace: inherit, branch (git worktree riêng biệt), share.
Phân quyền tool (Scoping) Quy định qua frontmatter allowed-tools trong .claude/agents/*.md. Cấu hình cờ enable_write_tools, enable_subagent_tools khi gọi define_subagent.
Tương tác Giao việc một chiều, subagent chạy xong trả output tổng kết về thread chính. Bất đồng bộ qua message: invoke_subagent, send_message, reactive wakeup khi có kết quả.

5. Bốn bẫy kiến trúc (Pitfalls) cần tránh

  • 1. Ping-pong / Banter Trap: Implementer và Reviewer tranh cãi qua lại về format code khiến cạn ngân sách token. Giải pháp: Luôn chặn cứng giới hạn vòng lặp (Max 2-3 iterations) và ưu tiên dùng Hook/Linter tất định thay vì tranh cãi bằng văn xuôi.
  • 2. Context Starvation (Handoff Amnesia): Gọi subagent với câu lệnh cộc lốc ("Sửa bug này đi") mà không cung cấp đường dẫn file, spec hoặc context cần thiết. Giải pháp: Giao việc kèm Briefing đầy đủ hoặc trỏ vào file spec chung trên đĩa.
  • 3. Workspace Collision: Hai subagent cùng ghi đè vào một file đồng thời gây mất mát mã nguồn. Giải pháp: Dùng chế độ phân nhánh branch (git worktree) hoặc chỉ cho phép một implementer sửa code tại một thời điểm.
  • 4. Over-engineering (Lạm dụng): Tách 3 subagent cho một sửa đổi 2 dòng code. Quy tắc: Chỉ dùng subagent khi cần cô lập lượng đọc lớn (>20k tokens) hoặc cần phân quyền (agent chỉ đọc vs agent ghi).
