Glossary

Ngôn ngữ chuẩn của khóa này, nối tiếp glossary của llm-foundation (token, context window, stateless call, prompt caching… đọc ở đó). Một thuật ngữ chỉ vào đây khi Luật đã dùng đúng nó.

Quy ướcThuật ngữ giữ tiếng Anh. Định nghĩa nói thứ đó là gì. Dòng Tránh liệt kê cách gọi lỏng lẻo không dùng trong workspace.

Coding agent

Harness:
Phần code bao quanh model trong một agent: giữ vòng lặp, cung cấp và thực thi tool, quản lý context, kiểm soát quyền. Model chỉ sinh text; mọi thao tác thật đều do harness làm.
Tránh: "Claude tự sửa file", "model chạy lệnh".

Vòng lặp ba pha (gather → act → verify):
Chu trình làm việc của một coding agent: tìm hiểu (đọc, tìm kiếm), sửa (edit, chạy lệnh), kiểm tra (build, test), lặp lại tới khi xong. Thiếu pha kiểm tra thì agent chỉ còn đoán.
Tránh: "agent tự chạy", "auto mode" khi nói về cấu trúc vòng lặp.

str_replace:
Cách sửa file bằng cách đưa đoạn cũ (old_string) và đoạn mới. Đoạn cũ phải khớp chính xác và khớp đúng một chỗ. Nếu vi phạm, tool trả lỗi về để model tự sửa cách gọi.
Tránh: "patch", "diff" khi nói về cơ chế này; "sửa dòng số N".

ReAct:
Mẫu vòng lặp xen kẽ nghĩ → làm (gọi tool) → quan sát (đọc tool_result). Quan sát thật chặn lỗi dây chuyền của suy luận thuần. Mọi coding agent hiện nay đều là ReAct, thường cộng thêm một plan tool mỏng.
Tránh: "agent tự suy nghĩ", "chain-of-thought" khi có gọi tool.

Instruction

System prompt:
Phần chỉ dẫn cố định do harness viết, nằm ngay sau tool definitions: vai trò, cách dùng tool, luật an toàn, môi trường. Đọc nó như một runbook: mỗi dòng chặn một lỗi đã từng xảy ra.
Tránh: gọi CLAUDE.md là "system prompt".

Instruction file (CLAUDE.md / AGENTS.md):
File chỉ dẫn do team viết, được harness đưa vào context. Với Claude Code, nó là user message nằm sau system prompt. Đây là context, không phải cấu hình bắt buộc: các file được nối lại với nhau, và khi mâu thuẫn thì model có thể chọn bừa.
Tránh: "config của agent", "luật bắt buộc".

Non-standard convention:
Quy ước kỹ thuật khác thường của dự án mà model không thể tự suy ra từ pre-training hay kiến thức phổ thông (custom wrapper, ID format, thư viện nội bộ). Đây là nội dung có ROI cao nhất trong instruction file.
Tránh: đưa kiến thức lập trình cơ bản vào AGENTS.md.

Prefix cache (Prompt caching):
Cơ chế cache các token ở phần đầu prompt nếu chúng không đổi giữa các lượt gọi. Yêu cầu nội dung ở phần đầu (system prompt, AGENTS.md) phải tĩnh tuyệt đối để không làm vỡ cache breakpoint ở phía sau.
Tránh: chèn ngày giờ hoặc lệnh biến động vào instruction file.

Hierarchical discovery (instruction):
Cơ chế nạp file chỉ dẫn phân cấp: file ở root nạp cho toàn repo, file ở thư mục con (sub-AGENTS.md) chỉ nạp khi agent thao tác trong phạm vi thư mục đó.
Tránh: gom hết quy ước của từng module con vào root file.

Hook:
Code do harness chạy tại một thời điểm cố định trong vòng lặp, ví dụ PreToolUse chạy trước khi tool được thực thi. Hook chặn được một hành động bất kể model quyết định gì. So với instruction file: hook giống constraint trong database, còn instruction file giống comment trong code.
Tránh: "rule", "guard" khi ý là lời dặn trong CLAUDE.md.

PreToolUse / PostToolUse:
Hai điểm neo vòng lặp quan trọng nhất: PreToolUse chạy trước khi tool ghi đĩa/chạy lệnh (dùng làm guardrail, exit khác 0 để abort); PostToolUse chạy sau khi tool xong (dùng làm lint/test gate, bắt stderr đưa vào context).
Tránh: nhầm lẫn giữa điểm chặn trước và điểm kiểm tra sau.

Guardrail (chốt chặn an toàn):
Cơ chế kiểm soát cứng nhằm ngăn chặn agent thực thi các hành động nguy hiểm hoặc vi phạm chính sách bảo mật (sửa migration đã merge, xóa database, leak secret). Thường được hiện thực qua PreToolUse hook.
Tránh: "system prompt reminder".

Tight feedback loop (vòng lặp phản hồi chặt chẽ):
Quy trình tự động hóa việc đưa lỗi từ compiler, linter hoặc test runner trực tiếp vào context của agent ngay sau mỗi thao tác sửa code, giúp model tự sửa lỗi mà không cần con người can thiệp.
Tránh: chờ human code review mới báo lỗi cú pháp.

MCP

MCP host / client / server:
Host là ứng dụng AI (Claude Code) quản lý các client. Client là một kết nối bên trong host, ứng với đúng một server. Server là process cung cấp tools, resources, prompts.
Tránh: "Claude Code là MCP client" (nó là host chứa nhiều client), "cài MCP" khi ý là thêm một server.

Primitive (tools / resources / prompts):
Ba loại thứ server cung cấp, phân biệt bằng ai quyết định dùng: tools do model gọi, resources do ứng dụng đưa vào context, prompts do người dùng chọn.
Tránh: gọi mọi thứ server cung cấp là "tool".

Transport (stdio / Streamable HTTP):
Đường đi của message MCP. stdio: server là process con, stdout là đường truyền. Streamable HTTP: server là service với một endpoint nhận POST, xác thực bằng OAuth 2.1. HTTP+SSE là transport cũ, đã deprecated.
Tránh: "SSE server" khi nói về server HTTP hiện đại.

Tool execution error vs protocol error:
Tool execution error nằm trong result với isError: true, model đọc được và tự sửa. Protocol error là JSON-RPC error (sai cấu trúc, method lạ), dành cho người viết client. Lỗi nghiệp vụ phải đi đường thứ nhất, kèm message chỉ cách sửa.
Tránh: "tool bị crash" khi tool trả lỗi có chủ đích.

Thiết kế tool

Namespacing (tool):
Đặt tiền tố chung cho các tool cùng nhóm (learn_get_progress, learn_list_topics) để model phân biệt ranh giới khi có nhiều tool từ nhiều server. Claude Code tự thêm mcp__<server>__, nhưng đó là cho permission và hook; tên tool vẫn nên tự mô tả.
Tránh: tên chung chung như search, get_data.

Unit test tool vs tool eval:
Unit test kiểm tra hợp đồng của server (schema, message lỗi, kích thước output) qua in-memory client, tất định, chạy mỗi commit. Tool eval chạy agent thật trên bộ task và đo đúng, số lần gọi, số lỗi, token; kết quả là con số có nhiễu, chạy khi đổi thiết kế.
Tránh: "test bằng cách hỏi thử agent vài câu" khi muốn nói về eval; gọi eval là "test pass".

Skill

Skill:
Thư mục gồm SKILL.md (frontmatter + chỉ dẫn), tài liệu tham chiếu và script, được agent nạp khi việc hiện tại khớp với description. Đóng gói cách làm, khác MCP tool đóng gói năng lực.
Tránh: gọi skill là "plugin" (plugin là gói phân phối, có thể chứa skill, hook, MCP server) hay "prompt template".

Progressive disclosure:
Cách nạp context theo tầng: metadata của mọi skill luôn có mặt, thân skill nạp khi được gọi, tài liệu và script chỉ mở hoặc chạy khi chỉ dẫn bảo cần. Mục đích là chỉ trả token cho phần việc hiện tại cần.
Tránh: dùng như từ đồng nghĩa với "tóm tắt" hay "RAG".

Trigger (skill):
Việc model quyết định gọi một skill, chỉ dựa trên name và description trong listing. Undertrigger: không gọi dù skill có ích, hay gặp khi model tự tin tự làm được. Đo bằng trigger eval có cả câu dương và câu âm.
Tránh: "skill tự chạy".

Memory

Working memory (bộ nhớ làm việc):
Toàn bộ context window của lượt gọi hiện tại (system prompt, lịch sử hội thoại gần, tool results). Tồn tại ngắn hạn, mất sạch khi phiên kết thúc hoặc bị nén sau compaction.
Tránh: "bộ nhớ của model", "RAM của máy".

Episodic memory (bộ nhớ trải nghiệm):
Nhật ký các sự kiện, hành động và kết quả đã diễn ra trong quá khứ gắn với mốc thời gian cụ thể. Giúp agent học từ lỗi sai cũ và tiếp nối mạch làm việc qua các phiên.
Tránh: "chat history" khi ý chỉ lịch sử của nhiều phiên trước; "vector database".

Semantic memory (bộ nhớ ngữ nghĩa):
Tri thức, sự thật, sở thích và quy tắc đã được đúc kết thành khái niệm độc lập với thời gian. Thường được lưu dưới dạng fact hoặc file ghi chú có cấu trúc.
Tránh: nhầm với episodic memory; "kiến thức học từ pre-training".

Procedural memory (bộ nhớ quy trình):
Kỹ năng và cách thức thực hiện hành động: mã nguồn tool, định nghĩa skill, playbook quy trình, script tự động hóa. Đóng gói cách làm thay vì sự thật.
Tránh: gọi mã nguồn hay tool là "semantic memory".

Consolidation (đúc kết / hợp nhất ký ức):
Quá trình chuyển hóa các sự kiện rời rạc từ episodic memory thành tri thức cô đọng trong semantic memory, loại bỏ chi tiết thừa và cập nhật mâu thuẫn.
Tránh: "tóm tắt hội thoại", "nén context".

Memory decay / forgetting (quên / loại bỏ ký ức):
Cơ chế vô hiệu hóa hoặc xóa bỏ các ký ức đã cũ, sai lệch hoặc mâu thuẫn để tránh context rot và dirty read. Tương đương cache eviction / invalidation trong backend.
Tránh: "xóa lịch sử chat", "reset model".

Multi-agent & Subagent

Subagent:
Tác tử con được sinh ra với ngữ cảnh cô lập (context fork) để giải quyết một nhiệm vụ chuyên biệt, sau đó chỉ trả kết quả cô đọng về cho agent chính. Giúp dọn sạch rác trung gian và bảo vệ context chính.
Tránh: "gọi API LLM thông thường", "prompts lồng nhau".

Context fork:
Kỹ thuật tạo một nhánh ngữ cảnh độc lập tạm thời cho subagent thực thi, vứt bỏ toàn bộ lịch sử các bước đọc file hay thử sai trung gian sau khi hoàn tất tác vụ.
Tránh: "mở session chat mới".

Orchestrator-Workers:
Mô hình kiến trúc phân cấp (hierarchical) trong đó agent điều phối (orchestrator) phân tích mục tiêu, chia nhỏ công việc cho các worker chuyên biệt (researcher, implementer, reviewer) và tổng hợp kết quả cuối cùng.
Tránh: "nhóm chat tự do", "multi-agent không người điều phối".

Handoff artifact:
Vật phẩm chuyển giao có cấu trúc (file spec, checklist, diff patch, test report) được truyền giữa các agent trong pipeline thay vì nhồi nguyên lịch sử hội thoại tự do không kiểm soát.
Tránh: "tin nhắn chat qua lại".

Ping-pong loop (Banter trap):
Bẫy tương tác đa tác tử khi hai hoặc nhiều agent trao đổi, tranh luận hoặc khen ngợi nhau qua lại vô tận mà không tạo ra bước tiến kỹ thuật nào, làm cạn kiệt ngân sách token và gây treo hệ thống.
Tránh: "agent đang hợp tác chặt chẽ", "tranh biện đa góc nhìn" khi không có tiến triển.

Agent-Ready Codebase & Eval

Agent-ready codebase:
Kho lưu trữ mã nguồn được cấu trúc và tài liệu hóa có chủ đích để coding agent có thể tự động khám phá, sửa mã, và xác minh độc lập thông qua công cụ tất định và vòng lặp phản hồi siêu tốc.
Tránh: "repo có nhiều tài liệu README", "code viết cho người đọc".

Fast feedback test subset:
Tập hợp con các bài kiểm thử đơn vị độc lập chạy cực nhanh (< 15–30 giây) để agent dùng làm quan sát phản hồi (feedback observation) trong vòng lặp ReAct, tách biệt với test suite tích hợp chạy hàng chục phút.
Tránh: "chạy full regression test sau mỗi turn", "bỏ qua khâu viết test".

Hermetic build:
Quy trình build hoàn toàn khép kín và tự túc, chỉ phụ thuộc vào các công cụ đóng gói sẵn trong repo (như ./mvnw hoặc ./gradlew), không đòi hỏi cấu hình máy chủ hay biến môi trường ngầm định.
Tránh: "build script chạy được trên laptop của tech lead".

Agent-ready scorecard:
Thang đo định lượng (thường là thang 100 điểm) gồm các tiêu chí về instruction, build, test, linter, containerization và guardrails để đánh giá mức độ thân thiện và an toàn của codebase đối với coding agent.
Tránh: "đánh giá cảm tính", "code smells thông thường".

Agent-level eval:
Phương pháp kiểm thử tự động toàn diện từ đầu đến cuối (E2E), đánh giá khả năng của coding agent trong việc giải quyết một bài toán lập trình thực tế qua nhiều lượt gọi tool trong môi trường cô lập.
Tránh: "chấm điểm prompt", "hỏi chatbot một câu".

Evaluation oracle:
Cơ chế hoặc nguồn chân lý tất định (thường là bộ automated tests) dùng để xác minh xem agent đã thực sự giải quyết được bài toán kỹ thuật hay chưa, phân biệt với việc dùng LLM để chấm điểm cảm tính.
Tránh: "LLM tự chấm điểm", "người đọc bằng mắt".

Fail-to-Pass (F2P):
Bài kiểm thử thất bại ở trạng thái mã nguồn ban đầu (chứng minh lỗi đang tồn tại) và phải chuyển sang trạng thái thành công sau khi agent sửa xong (chứng minh lỗi đã được giải quyết triệt để).
Tránh: "unit test thông thường", "smoke test".

Pass-to-Pass (P2P):
Toàn bộ các bài kiểm thử hồi quy cũ phải tiếp tục thành công sau khi agent can thiệp, chứng minh agent không phá hỏng các chức năng sẵn có của hệ thống.
Tránh: "kiểm thử tính năng mới".

Agentic Code Review

c-CRAB (Code Review Agent Benchmark):
Bộ benchmark thực chứng (arXiv:2603.23448, 2026) đánh giá năng lực của AI code review dựa trên kết quả hành động (Outcome-based Verification): kiểm tra xem một coding agent khác có thể dựa vào nhận xét review để sửa mã và vượt qua bộ unit test tự động hay không, thay thế cho độ đo tương đồng câu chữ BLEU/ROUGE.
Tránh: "chấm điểm văn phong review", "đo bằng BLEU/ROUGE".

Reviewer fatigue:
Hiện tượng kiệt quệ tâm lý và giảm sút độ tập trung của kỹ sư con người khi phải đọc thẩm định quá nhiều mã nguồn do AI sinh ra với tốc độ dồn dập, dẫn tới hành vi phê duyệt qua loa (rubber-stamping "LGTM") làm lọt lỗi nghiêm trọng vào nhánh chính.
Tránh: "lười biếng thông thường", "quá tải task".

Context myopia (Code review):
Chứng cận thị ngữ cảnh khi AI review chỉ được cung cấp một đoạn git diff đơn thuần mà thiếu thông tin toàn cục về các lớp cha, hàm gọi bên ngoài (callers), cấu hình bean hoặc schema cơ sở dữ liệu, dẫn tới các cảnh báo sai lệch và ảo giác.
Tránh: "model bị ngu", "thiếu prompt".

Self-critique filter (Code review):
Tầng kiểm duyệt phản biện trung gian trong đường ống review, bắt model tự sát hạch độ tin cậy (>80%), loại trừ các lỗi format thuộc thẩm quyền của linter, và đảm bảo mọi phát hiện đều có mã sửa mẫu cụ thể trước khi đăng lên PR.
Tránh: "đăng trực tiếp nhận xét thô", "chỉnh prompt một lần".

Noise-to-signal trap:
Bẫy tỷ lệ tín hiệu/nhiễu khi bot review xuất ra quá nhiều lời phê vặt vãnh (nits) về phong cách viết mã, gây ra kiệt quệ cảnh báo (Alert Fatigue) khiến lập trình viên bực bội và bỏ qua các cảnh báo lỗi bảo mật chí mạng.
Tránh: "bot review càng chi tiết càng tốt".

REVIEW.md:
Bản hợp đồng kỹ thuật ở cấp độ repository (chuẩn của Anthropic / Claude Code) quy định luật chơi review: phạm vi diff, danh mục check, những thứ cấm báo (style, ngoài diff), giới hạn minor và kỷ luật vòng lặp.
Tránh: "hướng dẫn chung", "ghi chung vào README".

Skeptical verifier (Code review):
Subagent thẩm định độc lập chạy với ngữ cảnh sạch (clean context) và tâm thế hoài nghi, có nhiệm vụ lần theo từng dòng mã thật để chứng minh hoặc bác bỏ các finding nghiêm trọng (blocker/major) do các lens phát hiện trước khi xuất bản lên PR.
Tránh: "voting bằng các auditor giống nhau", "tin ngay phát hiện đầu tiên".

Code thân vs code lá (Risk-based review):
Chiến lược phân bổ chú ý dựa trên bán kính sát thương (blast radius) của John Kim (Meta): code thân (hạ tầng, shared state, migration) bắt buộc người đọc từng dòng; code lá (UI lẻ, độc lập, sau flag) đọc lướt hoặc tự động merge.
Tránh: "đọc kỹ mọi PR như nhau", "bình đẳng mọi dòng code".

Failure scenario (Kịch bản hỏng):
Tiêu chuẩn bắt buộc cho mọi finding hợp lệ: phải viết được cấu trúc "input/trạng thái X -> hệ thống làm Y, đáng lẽ Z" kèm trích dẫn file:line cụ thể. Đây là thước đo duy nhất để phân biệt bug kỹ thuật thật với cảm giác chủ quan.
Tránh: "góp ý cảm tính", "nhận xét chung chung không có kịch bản".
