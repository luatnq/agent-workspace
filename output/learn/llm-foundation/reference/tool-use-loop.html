Tool-use loop

Vòng lặp, hình dạng message, luật format, xử lý lỗi, và checklist thiết kế tool. Đi kèm Bài 3.

Vòng lặp

loop (có guard: max_iterations, token budget):
  resp = call(model, tools, messages)
  messages += assistant(resp.content)            # giữ nguyên mọi block, kể cả thinking
  if resp.stop_reason == "max_tokens": xử lý cụt, không chạy tool
  if resp.stop_reason != "tool_use": break        # end_turn | refusal | pause_turn…
  results = run_all_concurrently(resp.tool_use_blocks)
  messages += user(results)                       # MỘT message, tool_result đứng TRƯỚC text

Hình dạng block

BlockNằm trongTrường
tool definitiontools[] của requestname, description, input_schema (JSON Schema), tùy chọn strict: true
tool_usemessage assistantid, name, input
tool_resultmessage usertool_use_id, content (string | text/image/document blocks), is_error?

Không có role tool. Tool result về mặt model là "user nói cho tôi" → nội dung ngoài tầm kiểm soát là untrusted.

Luật format (vi phạm → 400)

  1. tool_result phải ở message ngay sau message chứa tool_use; không chen message khác.
  2. Mọi tool_use phải có đúng một tool_result khớp tool_use_id — kể cả khi tool lỗi.
  3. Trong user message, các tool_result đứng trước mọi text block.
  4. Nhiều tool_use trong một response → tất cả result trong một user message (tách ra: dạy model bỏ parallel).
  5. Có thinking: trả lại block thinking nguyên vẹn (có signature) cùng tool result.

tool_choice

Giá trịHành vi
auto (mặc định)Model tự quyết; thêm disable_parallel_tool_use: true để tối đa một call/lượt
anyBắt buộc gọi một tool nào đó
tool + nameBắt buộc gọi tool này (structured output nay ưu tiên output_config.format)
noneKhông gọi tool

Không gọi tool như kỳ vọng → thêm vào system prompt: "Use the tools to investigate before responding." Gọi quá nhiều → "Use your judgment about whether to call a tool or respond directly."

Xử lý lỗi

Tình huốngLàm gì
Tool ném lỗi (500, timeout)is_error: true + message nói cái gì sai và nên thử gì ("Rate limit exceeded. Retry after 60 seconds.")
Thiếu / sai paramis_error: true + "Missing required 'location'"; model retry 2–3 lần. Phòng ngừa: strict: true, description rõ
Result quá lớnCắt (Claude Code: trần 25k token) + kèm hướng dẫn cách hỏi hẹp hơn; hoặc pagination / response_format
Hành động không hoàn tácGuard ở app (confirm, allowlist, dry-run), không ở prompt
Loop không kết thúcmax_iterations, ngân sách token, phát hiện gọi lặp cùng tool cùng input

Chi phí mỗi vòng

  • Tool definitions: gửi lại mọi request.
  • System prompt tool use: API tự chèn (~286 token Opus 5 / ~354 Sonnet 5 với auto; ~120 token hơn với any/tool).
  • tool_use: output token. tool_result: input token, tồn tại đến hết hội thoại.
  • Server tools: web search $10 / 1,000 lượt; web fetch chỉ tính token.

Checklist thiết kế tool

  • [ ] Gộp theo workflow (schedule_event), không wrap từng endpoint
  • [ ] Search có limit thay vì list unbounded
  • [ ] Namespace: hệthống_resource_hànhđộng
  • [ ] Trả tên/mã người đọc được; UUID chỉ khi bước sau cần
  • [ ] response_format: concise | detailed
  • [ ] Pagination / truncation với default hợp lý; thông báo cắt kèm hướng dẫn
  • [ ] Error message có hành động tiếp theo
  • [ ] Description viết như cho new hire; tên param không mơ hồ (user_id)
  • [ ] Eval bằng task thật nhiều bước; đo accuracy, số call, token, error; đọc transcript
