Self-host inference

Tính nhanh VRAM, chọn knob vLLM, dựng dashboard và HPA, quyết định self-host hay API. Đi kèm Bài 8.

Hai pha

PhaNghẽn ởMetricĐòn bẩy
Prefill (đọc prompt)ComputeTTFTPrefix caching, prompt ngắn hơn, max_num_batched_tokens lớn
Decode (sinh token)Băng thông bộ nhớITL / TPOTQuantize weights, GPU băng thông cao, max_num_batched_tokens nhỏ

latency = TTFT + TPOT × output tokens. Trần decode ở batch 1 ≈ băng thông ÷ dung lượng weights. Batching tăng throughput gần như miễn phí vì weights chỉ đọc một lần mỗi bước, và giới hạn của batch là chỗ trống trong KV cache.

Tính VRAM

weights  = params × bytes        BF16 2 · FP8 1 · INT4 ~0.5
KV/token = 2 × layers × kv_heads × head_dim × bytes
KV free  = VRAM × 0.92 − weights − overhead
seqs     = KV free ÷ (KV/token × context)

Kubernetes

  • Routing: không round-robin. Dùng router chọn pod theo queue, KV usage, prefix cache: Gateway API Inference Extension (v1) · llm-d (v0.9) · vLLM production-stack · KServe.
  • HPA: scale theo queue size (tối ưu throughput/cost) hoặc batch size (tối ưu latency). Không scale theo CPU. Không scale theo GPU memory, vì vLLM chiếm trước nên metric này chỉ scale lên. GPU utilization không đo lượng việc có ích.

Self-host khiAPI khi

Câu hỏi kiểm tra mọi con số "self-host rẻ hơn": giả định GPU bận bao nhiêu phần trăm? GPU tính tiền theo giờ, nên cost mỗi token tỉ lệ nghịch với độ đầy của batch.
