Context & caching

Checklist để thiết kế và debug prefix, tính điểm hoà vốn của cache, và chọn cách giữ context sạch. Đi kèm Bài 7.

Nguyên tắc

  • Mục tiêu: "smallest possible set of high-signal tokens that maximize the likelihood of some desired outcome."
  • App chọn context ở mỗi lượt. Tool result, lịch sử, file: thứ gì vào context là do code của anh quyết định.
  • Không đổi đặt trước, hay đổi đặt sau. Thứ tự: tools → system → KB/tài liệu tĩnh → lịch sử → message user cuối (ngày giờ, tên user, quyền ở đây).
  • Đo, đừng tin: assert cache_read_input_tokens > 0 từ request thứ hai trở đi.

Điểm hoà vốn

TTL 5m:  1.25 + 0.1*k  <  1 + k    =>  k >= 1 hit
TTL 1h:  2.00 + 0.1*k  <  1 + k    =>  k >= 2 hit

Chọn TTL theo khoảng cách giữa các request: dưới 5 phút → 5m · 5–60 phút → 1h · trên 60 phút → không cache.

KB nhỏ: prompt hay RAG?

Dưới ~200k token (~500 trang) thì nhét cả KB vào prompt + cache (Anthropic, 2024). Ví dụ: KB 80k, Sonnet 5, cache luôn ấm → ~$0.016/câu cho phần KB, rẻ hơn RAG top-20 × 800 token (~$0.032). RAG thắng khi: KB đổi liên tục · phân quyền theo user · context rot đo được trong eval · cần trích dẫn tới từng đoạn.
